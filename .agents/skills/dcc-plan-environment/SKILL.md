# Plan an environment task

Work from the user's brief and the active build plan. Read `docs/PILOT_USAGE.md` in the harness repository for actual commands. This skill supports the advisory pilot; it does not start a background agent.

Inspect the live document and connection first. Preserve unsaved work in a recovery copy before creating an owned test scene. Identify the active file/scene and what may change.

Write a brief with the intended composition, six to eight asset families where appropriate, dimensions in meters, shared material families, lighting intent, and three fixed review views. Classify references as dimension evidence, construction evidence or mood guidance; mark inferred dimensions. Do not use image overlap against a mood board as a dimensional requirement.

Confirm that at least one detail view actually shows the proposed edit at a useful scale; an unchanged set of cameras may miss a new task region. Freeze comparison views before authoring. When occlusion is a requirement, define the target, camera and supported visibility measurement in the brief; a generic clearance box does not prove visibility.

For an edit, state the requested delta and the locks: unrelated geometry, placements, cameras, shared material definitions and lighting. Assign one scope to each task. Repeated placements share an asset definition but have different instance IDs.

Choose a small acceptance checklist that would reject a plausible wrong result: hero dimensions, meaningful geometry, actual material bindings, visible silhouette and a legible focal hierarchy. A placeholder with the right name is insufficient. Keep artistic judgment separate from numeric assertions.

Use existing materials/assets when they fit the brief. Keep texture scale, color spaces and provenance explicit. Freeze inputs, instructions and resource ceilings before comparative trials. Do not expand a prop task into a complete rigging/export workflow.

Persist the brief, desired spec and continuation note with the project. Record routine assumptions and continue within the user's authorization; ask only for decisions that materially change their request or accepted constraints.
