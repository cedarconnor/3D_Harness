## Warnings, incident and verification limits

Detached rendering previously discarded its `Popen` handle while the exact child still ran. The retained probe established later child exit, not a persistent orphan. Task 4 adds a daemon reaper retaining the owned handle until exit without delaying detached startup or keeping a short-lived caller alive. The regression uses an actual owned child and asserts no `ResourceWarning`, nonblocking return, and automatic `returncode` population without test-side poll/wait. It failed before the fix; all 20 render tests passed afterward. No warning filter was added to production.

**Task 3 review M1: dependency warning investigated; remains open.** Narrow dependency probe: `mcp==1.26.0`, `pydantic==2.14.1`, `pydantic-settings==2.16.1` on the local environment. Importing FastMCP alone was clean; first `FastMCP(...)` construction emitted `IncompleteFieldDefinitionWarning` for the upstream `Settings.lifespan` forward reference. `Settings.__pydantic_complete__` changed from false to true during construction and the default lifespan was `None`. This reproduces independently of harness code. No dependency upgrade, monkey patch or suppression was introduced; the warning and transitive-version sensitivity remain open. A passing suite must not be described as warning-free.

**Task 3 review I2: unresolved historical preference incident.** an initial Task 3 GUI qualifier supplied a nonexistent owned config directory. Blender fell back to its real per-user 5.1 config and the fixture saved `userpref.blend` there. The owned process exited; no artist process was controlled. There is no verified prior baseline/backup, so prior existence/content and the extent of preference loss cannot be established. No global restore/deletion was attempted. Post-incident private preference copies remain local and are not published. Failed native logs remain retained. Subsequent qualifiers precreate directories, run read-only exact CONFIG containment probes and guard that path again inside the worker before writes. Those successful owned-config tests establish isolation for those later runs, not restoration of the historical file. It would be false to say every test run was isolated.

Task 1's final full portable run was 618 tests, 616 passed and two host symlink skips at its historical state. Task 2's full baseline was 639 tests with two skips before later bounded host fixes. Task 3's full run was 654 tests with two skips and one failure in the malformed-fingerprint fixture `test_identical_divergence_snapshots_are_deduplicated`; the fixture was corrected and all 27 live regressions passed. Later Task 3 round 1 passed 52 portable tests and 16 native checks, plus independent reopen and owned preference restart. No final 654-test all-green claim exists for the post-review runtime. Failed logs and earlier native states remain evidence, not final release qualification.

Task 4 focused checks cover render lifecycle and distribution, plus doc links/rules closure and workflow parsing. Final review and the integrated source/installed/native gate belong to the next task after runtime freeze; product-specific artistic and production-scene qualification remains separate.
